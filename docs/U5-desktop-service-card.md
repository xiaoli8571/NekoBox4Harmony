# U5 桌面服务卡片方案

## 目标

为 NekoBox4Harmony 设计一个桌面服务卡片，提供连接状态识别、当前节点摘要和快速启停入口。本文只定义后续实现方案，本轮不修改 `module.json5`、卡片注册信息或构建配置。

## 信息层级

1. 主状态：已连接、连接中、未连接。
2. 当前节点：显示节点名称，空间不足时单行省略。
3. 运行时间：连接后显示与主界面一致的累计时长。
4. 流量摘要：显示实时上传和下载速率；未连接时显示资源化空态。
5. 主操作：提供连接或断开按钮，连接中禁用重复触发。

## 尺寸建议

- 2x2：状态、节点名称、主操作，优先保证可读性。
- 2x4：增加运行时间和上下行速率。
- 4x4：可增加最近节点和打开应用入口，但不在卡片内承载订阅编辑等复杂操作。

## 状态来源

- 复用现有 VPN 状态链路，不创建第二套连接状态。
- 展示层读取 `vpnRunning`、`vpnStatus`、`vpnRunningProfileId`、`vpnUpSpeed`、`vpnDownSpeed`。
- 运行时间与应用内 UI 统一读取 `uiUptime` 和 `uiUptimeStart`。
- `uiBreakpoint` 仅用于应用窗口布局，不用于卡片尺寸判断。

## 交互原则

- 主按钮只调用既有连接和断开能力，不在卡片侧复制 VPN 生命周期逻辑。
- 未选择节点时，点击连接应打开应用并引导选择节点。
- 所有操作需要节流，连接中不得再次发起连接或断开。
- 卡片刷新失败时保留最后一次稳定状态，并提供打开应用入口。

## 视觉原则

- 延续 B 方案纯色、hairline 和无渐变视觉。
- 不使用阴影、模糊、玻璃效果或大面积圆角卡片叠层。
- 深浅色均引用资源色，新增可见文本必须同步 base/en_US。
- 主操作尺寸满足触控热区要求，状态不能只依赖颜色表达。

## 后续落地步骤

1. 在允许修改卡片配置的独立迭代中确认服务卡片 API 和最低系统版本。
2. 增加卡片 provider、布局资源和 module 注册信息。
3. 建立卡片与既有 VPN 服务之间的受控事件通道。
