# U5 桌面服务卡片 2×2 / 2×4 方案

> 状态：仅完成条件任务要求的设计方案，等待用户明确解除 `module.json5` 冻结后再实现。
>
> 本文依据 `dev-doc-01-设计规范.md` §7、`dev-doc-01C-玻璃霓虹规范.md` §5、`dev-doc-02-架构与数据流.md` §7、`dev-doc-03-任务拆分与验收.md` P5 编写。当前阶段不修改 `entry/src/main/module.json5`，不新增 FormExtensionAbility 实现，不接入主应用 Store，也不执行构建、打包或 Git 写操作。

## 1. 目标与边界

计划提供两张 HarmonyOS 桌面服务卡片：

- `vpnCard22`：2×2 一键连接卡，突出连接状态、当前节点和主开关。
- `vpnCard24`：2×4 快速控制卡，提供三个节点快切入口、当前模式和速率摘要。

实施边界：

1. 卡片进程只消费 Form 注入数据，并以共享 Preferences 中的最近快照作为冷启动兜底。
2. 卡片进程不得 import 主应用 Store、VPN 服务或订阅模块。
3. 卡片内不开 blur，玻璃感通过实底、半透明描边、渐变、层级和留白表达。
4. 卡片动作只通过 `postCardAction` 回传，由 `VpnFormAbility` 拉起 `EntryAbility`，再由主应用既有状态链路消费。
5. 所有传输字段必须是可无损 JSON 序列化的基础类型，不跨进程传递 live object。

## 3. `form_config.json` 草案

以下仅为字段意图草案。正式实现前必须以当前 HarmonyOS 6.1 SDK 或 DevEco 生成模板核对字段名、尺寸枚举、路径格式和扩展能力 metadata 结构。

```json
{
  "forms": [
    {
      "name": "vpnCard22",
      "description": "$string:form_vpn_card_22_desc",
      "src": "./ets/form/formwidget/FormWidget22.ets",
      "uiSyntax": "arkts",
      "isDefault": true,
      "colorMode": "auto",
      "defaultDimension": "2*2",
      "supportDimensions": ["2*2"],
      "updateEnabled": true,
      "updateDuration": 1,
      "defaultColor": "#0B0F1A"
    },
    {
      "name": "vpnCard24",
      "description": "$string:form_vpn_card_24_desc",
      "src": "./ets/form/formwidget/FormWidget24.ets",
      "uiSyntax": "arkts",
      "isDefault": false,
      "colorMode": "auto",
      "defaultDimension": "2*4",
      "supportDimensions": ["2*4"],
      "updateEnabled": true,
      "updateDuration": 1,
      "defaultColor": "#0B0F1A"
    }
  ]
}
```

`defaultColor` 仅是系统加载卡片内容前的占位背景。两张卡片均使用 `#0B0F1A`，避免深色方案 C 加载时闪出亮底。实际背景由 FormWidget 自绘。

## 4. `module.json5` 注册设计

解除冻结后，在现有 `extensionAbilities` 中追加 `VpnFormAbility`，不改动现有 `VpnExtAbility`：

```json5
{
  "name": "VpnFormAbility",
  "srcEntry": "./ets/form/VpnFormAbility.ets",
  "type": "form",
  "exported": true,
  "metadata": [
    {
      "name": "ohos.extension.form",
      "resource": "$profile:form_config"
    }
  ]
}
```

正式写入前必须用当前 SDK 模板验证 `type`、metadata 名称和 `srcEntry` 后缀。若 schema 与草案不同，只调整注册语法，不改变本文的数据流与安全边界。

## 5. 快照契约

`FormSnapshot` 使用稳定、扁平、JSON 安全的结构：

```text
running: boolean
connecting: boolean
mode: string
nodeId: string
nodeName: string
nodeFlag: string
latency: number
up: number
down: number
todayGB: number
updatedAt: number
quickNodes: FormQuickNode[]
```

每个 `FormQuickNode` 只包含：

```text
id: string
name: string
flag: string
selected: boolean
```

约束：

- `latency < 0` 表示未测或不可用。
- `up`、`down` 统一为原始字节每秒或统一数值单位，最终实现时沿用主应用现有速率格式化约定，不在桥接两端重复换算。
- `todayGB` 为显示层数值，仅保留合理小数精度。
- `quickNodes` 最多三个，由主应用从当前可选节点中投影生成。
- 禁止把 Profile、Store 或 Context 对象直接写入快照。

建议提供：

- `emptyFormSnapshot()`：返回断连安全默认值。
- `parseFormSnapshot(text)`：捕获 JSON 解析和字段缺失错误，失败时回退默认值。
- `sanitizeFormSnapshot(value)`：限制字符串长度、节点数量和非法数值，作为 Preferences 与 Form 注入的信任边界。

## 6. `FormBridge` 设计

`FormBridge` 位于主应用进程，职责单一：

1. 从已有状态中投影最小 `FormSnapshot`。
2. 将快照序列化到共享 Preferences 的 `vpn_form_snapshot`。
3. 对桌面卡片发布更新通知。
4. 对高频速率变化做 10 秒节流。

推荐行为：

- VPN 状态、模式或选中节点变化时立即推送。
- 仅速率变化时最多每 10 秒推送一次。
- 写 Preferences 成功后再发布，确保卡片冷启动兜底不落后于已发布数据。
- 单张卡片发布失败不影响其他卡片；记录错误但不破坏主应用连接流程。
- 生命周期结束时释放定时器或延迟任务。

`FormBridge` 不改变现有 Store 或 VPN API 契约。实施时复用当前真实状态来源，仅在其稳定更新点调用桥接方法。

## 7. `VpnFormAbility` 设计

### 7.1 创建与更新

- 创建卡片时读取共享 Preferences 的 `vpn_form_snapshot`。
- 解析失败或不存在时使用安全断连快照。
- 返回仅包含卡片所需字段的 Form 数据。
- 周期更新时重复读取最近快照，不主动启动 VPN 或主应用 Store。

### 7.2 事件回传

支持以下动作：

```text
toggle
select + nodeId
open
```

处理规则：

- `toggle`：启动 `EntryAbility`，参数 `vpnFormAction='toggle'`。
- `select`：先校验 `nodeId` 非空且长度合理，再启动 `EntryAbility`，参数包含 `vpnFormAction='select'` 与 `vpnFormNodeId`。
- `open`：只启动 `EntryAbility`，不附带状态变更动作。
- 未知 action 记录并忽略，不尝试执行。

Form Ability 不直接操作 VPN、Profile 或 Store，以免形成第二条不一致的业务链路。

## 8. `EntryAbility` 消费链路

`EntryAbility.onCreate` 与 `onNewWant` 统一解析卡片参数：

1. 验证 `vpnFormAction` 仅为 `toggle` 或 `select`。
2. `select` 必须同时具有合法的 `vpnFormNodeId`。
3. 写入 `AppStorage('pendingFormAction')` 与必要的节点 ID。
4. 首页进入前台后一次性消费动作。
5. 消费完成立即清空，防止旋转窗口、恢复页面或重复 Want 导致二次执行。

最终动作必须复用首页现有连接、断开和选中节点函数，不另写 VPN 控制分支。

## 9. 2×2 卡片视觉与交互

布局约 170×170vp，以系统实际卡片安全区为准：

- 背景：方案 C 深色蓝靛渐变，卡片进程内不开 blur。
- 内边距：12vp。
- 左侧：72vp 圆形能量球，电源图标 26vp。
- 右侧：连接状态 15fp/800；节点名、国旗和延迟 11fp。
- 断连：深色实底、低强度描边，状态显示“已断开”。
- 连接中：主球保持品牌色，使用静态高亮或系统允许的轻量反馈，不运行无限动画。
- 已连接：主球使用靛蓝到青色的方案 C 渐变与有限阴影。
- 整卡点击发送 `postCardAction('message', { action: 'toggle' })`。

卡片应为点按提供明确反馈，但避免高频或常驻动画造成桌面功耗。

## 10. 2×4 卡片视觉与交互

布局约 170×342vp：

- 背景：`#0B0F1A` 对应的深色实底视觉，叠加轻描边和静态渐变，不开启 blur。
- 第一行：左侧 `NovaVPN`，右侧状态点与规则模式。
- 第二行：三个等宽节点 chip。
  - 激活：方案 C 靛蓝到青色渐变、白字。
  - 未激活：`bg_glass_solid` 语义实底和次级文字。
  - 文案过长时单行省略。
- 第三行：上传、下载与今日流量，使用等宽数字语义。
- chip 点击发送 `postCardAction('message', { action: 'select', id })`。
- 标题区发送 router/open 动作，只打开应用，不改变 VPN 状态。

节点不足三个时只渲染可用节点，不生成无效占位按钮。

## 11. 降级与错误处理

- 无快照：显示已断开、无节点、速率占位值。
- 快照过期：仍显示最近数据，同时通过 `updatedAt` 判断并弱化状态，具体阈值实施时统一定义。
- 节点已删除：主应用消费 `select` 时按现有节点查找逻辑拒绝并提示，不在卡片侧假定有效。
- Preferences 读取失败：返回默认快照，不让卡片崩溃。
- 发布失败：保留 Preferences 快照，下次周期更新继续读取。
- App 未安装完整或能力启动失败：由系统处理，卡片不保留本地待执行队列。

## 12. 验收计划

解除冻结并实现后，按以下顺序验收：

1. 静态校验 `form_config.json` 与资源 JSON，无重复键、无 NUL、路径存在。
2. 核对 `module.json5` 只追加 form 能力，不改变现有 VPN Extension 与权限。
3. 核对 FormWidget 不 import 主应用 Store、VPN Service 或 core 模块。
4. 核对卡片 UI 不使用 blur，`defaultColor` 为 `#0B0F1A`。
5. 核对快照字段和事件参数均为 JSON 安全基础类型。
6. 核对 `toggle`、`select`、`open` 从卡片到 EntryAbility 再到既有业务方法的完整链路。
7. 核对待执行动作消费后清空，避免重复执行。
8. 核对 Preferences 冷启动兜底和单卡发布失败隔离。
9. 在允许构建的环境中再执行 SDK schema、编译和预览器验证。
10. 真机验证桌面添加、开关 VPN、节点快切、10 秒内刷新与杀进程后的最近快照。
