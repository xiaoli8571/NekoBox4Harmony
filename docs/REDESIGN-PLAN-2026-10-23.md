# NekoBox 全面改造实施方案（详细版）

日期：2026-10-23。项目：NekoBox4Harmony。规划基线：当前工作区 2.2.1 / 2200001、sing-box 1.14 OHOS 内核。

**文档状态：方案已编写，实施尚未开始。** 本文定义本轮全面改造的目标行为、工程路径和完成标准，不把“计划做”记为“已经完成”。此前功能检查与修复记录见 [功能审计](FUNCTIONAL-AUDIT-2026-10-23.md)。

用户要求：上一轮关于 UI、页面排布、节点、测速、分应用、分流、策略组、订阅、设置、视觉适配的建议全部进入实施范围，先形成详细方案。本文是新的改造依据：涉及这些项目时，早期“界面逐字复刻 Android”的要求让位于本轮体验改造目标；既有协议、数据、备份及平台约束继续保留。施工阶段同步更新 AGENTS/HANDOFF/DEVPLAN 中与新行为冲突的说明，保留历史背景，不篡改旧验收记录。

## 0. 阅读顺序与决策摘要

产品与交互：阅读第 1—13 节。数据、安全边界与工程：阅读第 14—19 节。排期与验收：阅读第 20—25 节。

本方案确定以下行为，实施时不再随意选择另一套口径：

1. 七个一级入口改为：**节点、订阅、分流、设置、日志、工具、关于**，保留现有顺序和抽屉框架；连接详情是二级页面。
2. 手机维持单列；宽屏提供列表与详情双栏。首页连接状态卡是原节点页的一部分，不新增独立 Web 仪表板。
3. 浏览选择、连接目标、内核实际出站分别建模；界面不得将三者混作“当前节点”。
4. “检测可用性”默认使用代理 HTTP 探测，结果持久化携带方式、目标、判据、时间及是否经过当前隧道；TCPing作为独立方式。
5. 新装默认 HTTP 判据为 2xx；旧装保留旧判据并明确显示，用户可切换。该探测只代表到测试目标的结果，不承诺所有网站和UDP都可用。
6. 一个坏节点不再使好节点整批退化为 TCPing。先做分批隔离；整轮内核不可用时才显式提供其他检测方式。
7. include 空名单禁止作为新配置连接或应用；绝不省略名单后扩大为全应用代理。运行中出现无效草稿不改变现行配置。
8. 分应用负责“哪些应用进入 VPN”；域名/IP 规则负责“进入后的流量走哪个出站”。普通鸿蒙应用按包名指定不同节点不作为可用能力展示。
9. 设置统一分为即时外观、下次操作生效、需要重连三类；网络变更进入待应用草稿，用户一次应用，避免每勾选一个应用就重启 VPN。
10. 远程规则集使用可靠的已验证缓存和明确的失败策略；没有可用缓存时默认阻止应用新配置，不静默删除关键规则。
11. 订阅原始数据与用户覆盖分开保存；更新先验证、再提交，失败保留上次可用数据。
12. 运行状态由扩展进程及实际内核信息确认；未收到确认不显示“应用成功”。
13. 既有半透明速率条、纯背景模糊、通知栏“速率＋运行时长”的用户偏好继续作为设计约束。
14. 内核ABI、权限和签名均有专门边界。优先应用层完成；确需新增内核能力时使用版本化导出并重新构建、打包、验收。

## 1. 目标、适用人群与成功标准

### 1.1 三类用户

| 用户 | 高频任务 | 产品应当提供的路径 |
|---|---|---|
| 普通使用者 | 导入、连接、换节点、更新订阅 | 首屏可见状态与主操作，基础功能无需理解JSON |
| 分流使用者 | 指定应用直连、域名走某组、检查规则 | 独立分流页面、清楚的策略说明、真实连接证据 |
| 高级使用者 | 代理链、DNS、IPv6、嗅探、覆盖配置 | 高级表单与JSON保留，明确冲突、能力和生效时机 |

### 1.2 产品验收目标

- 新安装从空页面到导入、选节点、授权、连接有连续引导；每一步失败都有可执行操作。
- 日常换节点、检测当前组、更新当前订阅不需要先打开大段高级设置。
- 用户在任一关键界面都能分清：草稿、已保存、待应用、运行中配置、错误。
- 不支持、未测、失败、过期、降级都用不同的状态表达；颜色只是辅助。
- 发生订阅更新失败、坏规则集、坏节点、进程重建时，原有数据和故障原因可追溯。
- 全部本轮建议必须具备实际入口、真实后端和验收证据；仅有模型字段、按钮或截图不算完成。

### 1.3 本轮范围边界

范围包括：七页重排与二级详情、所有既有入口迁移、测速完整流程、分流安全问题、策略组、订阅覆盖、设置应用机制、连接诊断、视觉与无障碍、数据迁移与回滚、手机平板真机验收。

本轮不引入新的付费服务或账户系统，不建设远端管理后台；不照搬其他客户端的MITM/脚本执行引擎。此前没有建议的这些能力不作为“全面改造”附带新增。按需连接等系统专属能力以鸿蒙可用API为前提，不能以苹果端存在作为实现依据。

## 3. 信息架构与导航

### 3.1 一级页面

| 页面 | 包含 | 不在本页直接展开的内容 |
|---|---|---|
| 节点 | 连接状态、模式、当前订阅/展示组、节点、测试进度 | 完整订阅管理、全部网络高级参数 |
| 订阅 | 订阅列表、导入、更新、流量/到期、详情 | 原始节点编辑表单、全局系统设置 |
| 分流 | 分应用、域名/IP规则、规则集、策略组四个子页签 | 仅影响主题的外观设置 |
| 设置 | 外观、启动、检测参数、DNS/IPv6/入站、高级参数 | 重复一套域名/IP规则编辑器 |
| 日志 | 日志过滤、错误事件、导出、查看连接入口 | 常驻大面积调试统计 |
| 工具 | 连通诊断、规则解释入口、STUN、备份恢复 | 常用换节点操作 |
| 关于 | 应用与真实内核版本、项目链接、更新、许可 | 调试用字段堆积 |

“模式”在节点页唯一提供主切换器；其他页只展示当前值或链接回去。分应用入口只在分流页维护；旧设置位置保留一个说明与跳转入口过渡一个版本，不维护第二份列表。

### 3.2 术语字典

- 节点：一个实际代理连接配置；不将订阅卡称为节点。
- 订阅：节点和可能的策略组的远端来源；界面名称不使用“新建分组”代替“添加订阅”。
- 展示分组：节点列表的分类与折叠；只影响浏览。
- 策略组：sing-box selector/urltest 出站；决定如何选择实际线路。
- 当前订阅：当前浏览的数据范围，不表示该订阅的所有节点都在运行。
- 已选节点：下次连接的候选项；运行中热切换未确认前不标为“正在使用”。
- 正在使用：运行配置实际解析到的出站；未知时明确显示“正在确认”。
- 规则／全局／直连：流量处理模式；“全部应用走VPN”不等于“所有流量强制代理”，流量仍受模式和规则控制。

这些术语在中英文资源、通知、日志摘要、导入向导、帮助说明中一致。存储字段和内部路由名可以保留兼容，避免只为改显示文案做危险的数据改名。

### 3.3 顶栏动作表

| 页面 | 常驻动作 | 更多菜单 |
|---|---|---|
| 节点 | 搜索、检测可用性 | 添加节点/导入、排序筛选、批量管理、连接列表 |
| 订阅 | 添加订阅、更新全部 | 导入文件、订阅导出 |
| 分流 | 按子页显示搜索、添加 | 导入/导出、待应用详情、规则解释 |
| 设置 | 搜索设置 | 恢复本分区默认值（明确作用域） |
| 日志 | 搜索、导出 | 清空当前日志视图、错误级别过滤 |
| 工具 | 当前工具所需动作 | 避免无作用的占位按钮 |
| 关于 | 无常驻业务动作 | 可使用文字行进入更新/许可 |

图标都提供无障碍名称；含义含混的连接图标改为“连接列表”文字或带清楚标签的入口。检测进行中，“检测”位置显示进度/取消。可用性依赖连接态的按钮给出原因，不能静默返回。

### 3.4 返回、恢复与上下文

- 抽屉打开先收抽屉；二级页先回父页；非节点一级页返回节点页；节点页返回桌面，沿用现有系统返回习惯。
- 编辑有未保存草稿时显示“继续编辑／保存草稿／放弃修改”；自动保存成功且没有未应用变化时不重复弹窗。
- 记住各页搜索、滚动、节点展示组、订阅选择、规则子页签。进程恢复时恢复浏览位置，但必须重新向扩展确认运行态。
- 日志、连接、规则解释从错误入口打开时携带 sessionId/connectionId/configRevision，返回原页面不丢上下文。

## 4. 节点首页与连接状态

### 4.1 手机首屏结构

```text
节点                          搜索  检测  更多
┌ 已连接 · 连通性待检测                     ┐
│ 正在使用：香港 01                        │
│ 本次 00:18:32     ↑ 24 KB/s  ↓ 2.1 MB/s │
│ [断开]          [检查连接]    [连接详情]   │
└─────────────────────────────────────────┘
[规则]                 全局                 直连
订阅 A ▾        分组：全部 ▾          12 个节点
收藏／仅看可用／排序                    （按需）
节点名称                         HTTP 86 ms
Trojan · 香港组                 2 分钟前检测
节点名称                        TCP 24 ms
Shadowsocks                    仅握手可达
                已完成 18/50       [取消]
```

这是信息层次草图，不是固定像素和颜色。折叠连接卡时保留状态、实际节点、主按钮；长列表滚动不让大型卡片挤占有效区域。现有底部半透明速率条继续提供运行摘要，避免与卡片重复显示过多相同信息。

### 4.2 两套状态必须独立

| 维度 | 状态 | 显示规则 |
|---|---|---|
| VPN会话 | 未连接/等待授权/连接中/已连接/切换中/断开中/连接失败/状态待确认 | 由扩展进程确认，带会话和代次 |
| 连通性 | 未检测/检测中/测试目标可达/测试失败/结果过期/受限检测 | 带时间、目标和方式，不能覆盖VPN会话状态 |

例如“VPN 已连接，测试目标超时”是合法组合。不能因为 HTTP 检测失败擅自关掉VPN，也不能因为TUN创建成功显示“网络正常”。

### 4.3 连接交互

1. 未连接：点连接→检查已选节点、应用范围、规则集缓存、配置合法性→请求系统授权→启动扩展→等待确认。
2. 配置不合法：停在当前页，定位具体字段与修复入口；不发起必然失败的重连循环。
3. 连接中：有进度文字和取消；重复点击不会启动第二份任务。
4. 已连接：主按钮为“断开”；检查连接是独立次操作。
5. 失败：卡片保留简短原因、时间、重试、查看详情。原生/内核原文放详情，不出现 `[object Object]`。
6. 请求超时：显示“未确认连接状态”，主动查询扩展；不能仅凭UI计时器将仍在运行的VPN标为断开。
7. 错误类别至少区分授权拒绝、配置无效、DNS失败、节点拒连、认证失败、超时、控制API不可用、系统终止。

### 4.4 当前使用与当前选择

浏览点选可以更新候选项；运行中同组selector选择走热切换流程。涉及重建时先进入切换中，待扩展确认后更新实际运行信息。失败保留此前已确认的实际状态；若旧会话已经失效则明确显示失败，不伪造“已回滚”。

自动优选时显示“策略：自动优选／实际：香港02”；连接目标仍指向策略组，不能每次自动换节点就改写用户的浏览选择。

### 4.5 空态与首次使用

- 无节点：主操作“导入订阅”，次操作“扫码／从文件／手动添加”；不显示可点击但必然失败的连接按钮。
- 导入后：显示节点数、被跳过的类型与原因，提供“检测可用性”和“选择后连接”。
- 无网络：保留已有节点和配置，显示网络不可用，不误报全部节点失效。
- 首次授权被拒：说明需要系统VPN授权，提供再次连接入口。
- 引导可关闭，不每次启动重复；不会自动读取剪贴板或自动访问未知订阅。

## 5. 节点列表与管理

### 5.1 节点行布局

主行是名称与正在使用标记；副行是协议、展示组或可选服务器地址；右侧是带方法的结果。名称可占两行或截断，完整内容在详情可复制。数字等宽对齐。

“正在使用”使用文字＋标记；“已选”使用边框/浅底。自动组实际成员不因列表刷新丢失。失败状态使用短文案和详情入口，不把所有失败都写成超时。

结果来源展示示例：`HTTP 86 ms`、`TCP 24 ms`、`HTTP 失败`、`旧结果`、`经当前VPN`、`未检测`。协议不支持TCPing时显示“不适用”，不记成失败或0ms。

### 5.2 可见操作与长按

行尾提供“更多”；长按调出同一动作源，避免两套菜单能力不同。常用操作为连接/选择、单节点检测、收藏、详情；编辑、分享、导出、移动分组、删除放更多。

删除带节点名称及影响说明；删除正在使用的节点前明确会发生什么。删除测试结果不等于删除节点。历史“置顶”迁移为收藏/置顶关系，原排序意图保留。

### 5.3 范围、搜索和批量

- 搜索覆盖名称、地址、协议；当前订阅和展示组范围在搜索框下可见。
- 排序提供原始/手动、名称、最近HTTP延迟、最近TCP延迟；不能把不同方式混在一个“最快”排序里。
- 未测与过期默认排在新鲜可用结果后，失败排最后；收藏优先与排序组合规则固定。
- “仅看可用”指新鲜且满足当前HTTP判据的结果；只有TCP结果的节点不被当作HTTP已验证。
- 批量模式支持检测、收藏、移动、导出、删除；顶部始终显示所选数量与范围。
- 批量检测默认当前可见数据范围；执行前标签明确“当前组18个/当前订阅80个/全部120个”。筛选改变后运行中的快照范围不跟着漂移。
- 去重和“删除不可用”归入批量管理；预览受影响节点再执行，旧结果、未测和不适用节点不能直接被当作不可用删除。

### 5.4 大列表

使用稳定ID、响应式视图模型与虚拟列表；不通过把名称、输入内容拼进ForEach key来强制刷新。结果最多每300ms合并刷新一次；输入框拥有独立草稿。5000节点下搜索与检测期间仍能滚动和取消，指标见§23。

## 6. 检测可用性与测速系统

### 6.1 入口与默认值

主入口“检测可用性”，附说明“通过代理访问测试地址并测量延迟”。方式选择为HTTP检测、TCPing；每种方式保存独立结果。该功能不测下载带宽，不能把延迟称为网速。

新装推荐HTTP＋2xx；旧装`any`保留为“收到HTTP响应即通过”，第一次进入检测设置时说明差异，不能静默改变已存判据。HTTP目标继承用户已保存的有效URL；无效时给出错误，不擅自替换成另一个服务。默认超时5s、并发5、取样1次、额外重试0次；高级设置可修改并受范围约束。

检测参数包括目标URL、超时、并发、取样数、失败重试、HTTP判据、是否尝试绕过当前VPN。提供“恢复推荐检测设置”，仅作用于此分区。

### 6.2 结果模型

新增`ProbeResult`，与节点配置独立存储，以`profileId＋profileConfigHash＋method＋target＋policy＋path`识别可比较结果。字段如下：

| 字段 | 用途 |
|---|---|
| runId / profileId / configRevision / profileConfigHash | 关联本轮、节点与测试时配置 |
| methodRequested / methodActual | HTTP请求和TCP回退不可混淆 |
| state | queued/running/success/failed/notApplicable/cancelled/unsaved |
| latencyMs / samples / aggregation | 延迟、采样数、聚合口径；0ms是合法数值，不用0表示未测 |
| target / timeoutMs / expectedStatus | 解释测到了哪里、用什么判据 |
| startedAt / completedAt / persistedAt | 显示结果新鲜度和是否真正保存 |
| path | directBound/currentTunnel/unboundUnknown/legacyUnknown；未知路径不假装直出 |
| errorCode / errorDetail / degradedReason | 友好文案与可展开原文 |
| coreCapability / source | 区分native V2/新版、手动/自动组/运行实例检测 |

现有桥接不回传成功HTTP状态码，不能凭空显示“204”；显示“满足2xx判据”即可。旧`status/ping/error/latencyMs`继续作为兼容投影，不作为新结果的完整事实来源。旧结果迁移为`method=unknown`、`path=unknown`，不能伪造为HTTP通过。

同一节点配置变化后，旧结果仍可在历史中查看，但不得参与“当前可用”过滤或自动优选。仅改名称/收藏不使传输配置hash失效。代理链及组前置/落地变化会使相关根节点hash失效。

### 6.3 运行与取消

- 创建不可变目标快照；运行中搜索、切页或订阅更新不改变本轮目标。
- 任务状态为准备→检测→取消中/完成/失败；完成摘要含成功、失败、不适用、取消、未保存数量。
- 节点开始时显示运行中，不提前清除其持久化旧结果；取消尚未执行的节点保留原结果并标明未参与。
- 完成结果写入独立检测日志，批量持久化并更新已保存计数；取消成功返回前刷盘。突然进程终止可恢复已保存部分，不能声称尚未刷盘部分也已保留。
- 节点被删除不复活；节点传输配置改变则该轮结果进入历史，不覆盖新配置结果；新增节点不被旧快照抹掉。
- 离开节点页可继续检测并有全局轻量进度入口；“取消”停止取新目标，处理中任务按取消上下文收尾。
- 检测结果刷新与存储写入解耦，禁止在每个结果到达时重建整个主页。

### 6.4 坏节点隔离算法

1. 先检测内核能力、测试目录可写性、URL合法性等整轮前提；环境级失败只报告一次，不把所有节点标成坏节点。
2. 对目标快照构建图并做静态字段检查，明显非法节点单独报错；保留其依赖链错误位置。
3. 正常情况启动一份批量测试实例，按tag并发探测，保持现有性能。
4. 批量初始化因节点配置失败时，清理旧实例，将目标拆成两组，串行尝试启动每组；成功组内部继续并发探测，失败组递归拆分，直到单节点隔离。
5. 共享的坏前置代理影响多个根节点时，各根节点都显示相同依赖错误，不错误地宣称只有一行有问题。
6. 隔离最坏启动次数上限约`2N−1`；设置累计准备时间上限与可取消状态。达到上限时报告未完成，不能偷偷改检测方式。
7. 明确识别为桥接不支持/环境级故障时，结束HTTP本轮并提供“改用TCPing检测支持的节点”。若用户已开启自动回退，实际结果和完成摘要必须永久标明TCP来源。
8. 全组绑定失败后的取消绑定重测只执行一次。`path`更新为未知或经隧道，不把一次toast作为唯一说明。

### 6.5 会话与桥接的并发约束

检测单例需要真正的会话隔离，不能仅在UI放一个`testing`布尔值。`ProbeCoordinator`统一管理UI入口、批量隔离、运行实例检测和自动测试请求。

- 每轮带runId/generation；旧回调不能更新新一轮。
- native start/probe/stop进入有序调度，stop完成并确认后才开始下一分批。
- Promise超时只代表UI等待超时，不代表native已停止。没有结束确认时禁止创建冲突测试实例，显示“内核检测任务正在收尾”。
- 如果现有ABI无法安全中止迟到start，实施K2：增加版本化会话导出，支持sessionId、取消标志及返回后校验；旧导出继续保留。迟到创建成功的实例必须立即关闭，不能被下一轮误复用。
- 不以卸载动态库或终止VPN扩展作为正常检测取消手段。
- DNS解析、TCP connect、HTTP请求、native桥接分别有超时；整体预算包括前置DNS，不能把只覆盖connect的3s描述成整轮3s。

### 6.6 检测结果的产品语义

HTTP成功代表测试目标可达；TCP成功代表握手可达；失败可查看原文；不支持的方法显示不适用；过期显示旧结果。取消不是失败。用户选择`any`时用“HTTP有响应”措辞，避免把403/500描述为正常访问。

“仅看可用”“最快节点”统一基于同方法、同目标、同判据、同路径、新鲜结果。自动组探测与手动探测若判据或路径不同，分别显示，不强行共用同一数值。

## 7. 域名/IP规则与规则集

### 7.1 分流页子页签

固定四项：**分应用、域名/IP规则、规则集、策略组**。首次默认到域名/IP规则；返回保留最近子页签。顶部展示“使用中的配置修订＋待应用变化数量”，统一应用入口见§12。

### 7.2 规则摘要列表

每条规则显示名称、匹配摘要、处理目标、启用状态和优先级；多条件显示“域名＋端口等3个条件（同时满足）”。一行可开关，点主体进编辑，更多支持复制/移动/删除。

规则排序可以显式上下移；拖拽作为可选增强，不能只有拖拽而没有可访问的替代操作。展示自定义规则与内置/订阅规则的来源及优先级关系。不能把按名称排序后的显示顺序误当内核优先级。

### 7.3 独立规则编辑器

基础：名称、匹配类型、匹配值、目标（直连/代理/拒绝/指定节点/指定策略组）、启用。

高级：目的端口、源IP/源端口、网络、嗅探协议、多条件AND、自定义JSON。高级条件未展开时仍显示已有条件数量，避免隐藏约束被用户误删。

输入校验覆盖域名格式、CIDR、IPv4/IPv6、端口及开区间、正则可编译、JSON对象类型、内核支持的字段和出站引用。保留正则原文；支持逗号与换行，空项去除，错误逐项定位。任何非法条件都不能被静默忽略后产生范围更广的有效规则。

编辑过程不改运行配置；保存先校验、再存草稿；应用时重新解析全部依赖。指定节点/组已删除时禁止应用并给替代目标选择，不自动改成proxy或direct。

条件关系必须显式建模：同一列表内的多个值默认OR，不同条件组按编辑器展示的AND/OR组合生成逻辑规则。sing-box默认规则对域名/IP类字段存在合并OR语义，不能把一个平铺JSON笼统描述成所有字段AND。旧规则迁移保留原内核实际语义并显示组合方式；用户改成严格AND时生成对应logical结构，单独验证DNS投影。

### 7.4 规则顺序与模式

配置生成器输出一份`CompiledManifest`：最终规则顺序、来源ID、出站映射、规则集版本、配置hash。规则解释与运行诊断都基于同一份实际修订。

- 规则模式按最终编译顺序执行，页面展示这个顺序；DNS嗅探/劫持/解析等技术前置动作与业务分流规则分区展示。
- 全局模式、直连模式的覆盖关系在页面说明，避免用户以为当前所有自定义规则都在生效。
- 新方案修正组播拒绝为“源或目的属于指定范围即拒绝”的明确逻辑结构，并用真实内核匹配验证；这是已记录的行为变更，需在升级说明中告知，不能只改注释。
- 私网绕过仍按独立开关，不与组播拒绝混用。
- 现有IPv4保护范围`224.0.0.0/3`还覆盖部分保留地址，不全部是纯组播。首轮保留现有范围并准确说明，仅修正源/目的OR关系；如后续缩小成`224.0.0.0/4`，须作为独立策略变化评估，不能借改名悄悄改变范围。
- 对DNS不能表达的流量条件，不生成一个删除了条件的更宽DNS拒绝规则。仅可准确投影的规则参与DNS路由；其他流量规则继续在连接路由阶段生效，并标记DNS投影限制。

### 7.5 规则集下载与缓存

规则集实体区分`editedAt / lastAttemptAt / lastSuccessfulDownloadAt / validatedAt / lastError`。下载状态来自下载服务和实际验证，不能再以编辑时间冒充更新时间。

新增下载流程：URL校验→下载到临时文件→检查响应/大小/格式→内核解析校验→计算hash→写入版本化资源目录→提交资源manifest→供配置引用。只有SR魔数不足以判定文件有效，必须验证完整SRS内容。实施K1提供无副作用的SRS验证入口；其能力不可用时不对资源标“已验证”。

| 场景 | 默认行为 |
|---|---|
| 首次下载成功且通过验证 | 允许应用，引用已验证本地版本 |
| 首次下载失败、无缓存 | 保留旧运行配置；新连接/新配置应用阻止并定位该规则集 |
| 更新失败、有已验证缓存 | 继续使用旧缓存，显示缓存时间与更新错误 |
| 下载200但内容损坏 | 不替换旧缓存，记录验证失败 |
| 用户明确暂停某规则集 | 作为有记录的策略修改进入待应用，而非下载失败时自动暂停 |
| 缓存丢失/旧版格式不兼容 | 重新验证/下载，失败按无可用缓存处理 |

资源快照按hash保留最近两个已验证版本；被运行配置或回滚配置引用的文件不清理。下载超时、失败重试、取消、单次体积上限和总缓存上限必须有界。规划初值：连接10s/读取30s、单文件32MiB、总缓存256MiB；大于阈值给明确错误，后续根据真实资产尺寸调整，禁止截断后当成功。

下载所有权选择为应用管理：编译时引用已验证的本地`rule_set`路径，避免同一资源又由应用下载又由内核remote定时更新。新资源以新hash存储，进入候选配置后按统一应用流程生效，不原地覆盖运行快照引用的文件。计划更新在系统允许应用执行时进行；页面区分计划时间与真实尝试时间，不承诺后台精确定时。该所有权与生效时机变化必须写入升级说明。

site/ip若继续保留，只作为分类；输入“格式”明确区分binary SRS与source JSON，不能混用分类和格式。现有仅CN内置资产不伪装成完整geosite分类库；不支持分类给出可导入规则集的替代路径。

## 8. 分应用代理

### 8.1 页面与文字

模式名称：全部应用走VPN／以下应用直连／仅以下应用走VPN。其说明明确“进入VPN后仍按规则/全局/直连模式处理”。

每条记录显示应用名称备注、鸿蒙包名、勾选；顶部显示有效勾选数量、格式错误数量、待应用数量。支持搜索、单个添加、批量导入、取消选择、删除条目。应用名称只用于显示，不参与系统名单。

现有预置应用目录继续保留但不承诺已安装；没有普通应用枚举权限时不增加虚假的“读取全部应用”按钮，也不能仅凭预置包名显示“已安装”。

### 8.2 空名单确定行为

- off＋任意列表：允许连接，系统不附加应用名单。
- exclude＋空列表：允许，界面说明“当前没有排除应用”。
- include＋空列表：草稿可保留；连接/应用被阻止，提示至少选择一个有效应用。
- 运行中取消include最后一项：保持旧运行配置；显示“草稿无有效应用，尚未应用”，禁止自动切换为全应用。
- 升级发现历史include空名单：记录迁移风险并要求修正后再应用；正在运行的旧会话不由迁移线程擅自改策略。

UI校验和扩展启动前校验各做一次，Want与磁盘读取分支必须执行同一纯策略函数。不能依赖按钮禁用作为唯一保障。

### 8.3 保存与应用

勾选立即保存为草稿，不每次重连；“应用更改”显示将影响多少应用及是否需要重连。已连接时应用仅执行一次串行重连；扩展回报configRevision和有效名单摘要后才显示已生效。保存失败保留草稿错误，不启动VPN；应用失败维持待应用并显示实际运行配置。

日志只记录模式、数量、revision及必要的脱敏摘要，详细包名在用户主动展开诊断时查看。包括CSV和JSON备份路径在内的所有入口都执行格式、去重和上限校验。

### 8.4 应用名单上限

按运行系统API版本选择有效上限：API23以前64、API23起256；界面显示当前上限。超限时阻止应用并定位数量，不静默截断后宣称全部勾选生效。历史超过上限的数据作为草稿保留，要求用户缩减。

### 8.5 按包名指定出站的历史数据

域名/IP规则编辑器中移除可正常输入的“包名指定出站”控件，改为平台限制说明和分应用入口。历史包含packages的规则归入“需处理的旧规则”：保留全部原文、旧启用状态与导出能力，不能只删packages后让其余条件扩大匹配范围。

迁移时将受影响规则标记`unsupportedOnPlatform`；应用前必须显式处理为保留暂停、改为支持的域名/IP条件或删除。不会自动把“按应用走香港节点”转换为“应用进入VPN”，因为二者语义不同。

## 9. 策略组与切换

### 9.1 可达的组管理

在分流→策略组管理手动选择、自动优选、成员、前置与落地代理；节点页可快速进入当前策略组。订阅导入的组显示来源与用户覆盖，不再藏在无UI绑定的方法里。

组卡显示名称、类型、实际成员、最后检测、是否正在承接流量。展示分组与策略组用不同图标及说明，不将所有展示分组自动转成内核selector。

### 9.2 手动选择与热切换

1. 读取运行`configRevision`、组tag、成员tag映射；确认当前组是selector且目标成员存在于运行图。
2. 通过已鉴权Clash API发PUT；tag来自稳定ID映射，不能拿可能重复的显示名称当标识。
3. 随后GET组状态，核对`now`；成功后更新实际出站状态和组选择持久化。
4. PUT失败不提前打“正在使用”标记，显示失败原因。
5. API不可用或成员不在运行图时，需要重建配置；提示将重连，按统一应用流程执行。不能把失败热切换当成无感成功。
6. 全局/规则指向的出站、前置代理或传输参数改变不在热切换范围内；统一说明为需要重连。

运行`profileId`指向连接根，不再承担所有场景的实际叶节点身份。自动组GET失败时显示“实际节点未知”，绝不用最低历史延迟推断当前成员。

### 9.3 自动优选

提供检测地址、间隔、容差、闲置暂停、是否影响现有连接等内核实际支持的参数；参数的支持情况随能力检测显示。默认建议沿用当前10min、容差50ms、不中断现有连接，变更必须明确可见。

自动优选结果来自内核group状态及历史，不用UI定时任务另造一套竞争选择器。显示“手动检测结果”和“内核自动检测”来源；检测目标/判据不同不共享可用性结论。

### 9.4 组图与引用

为每个策略组分配稳定ID和内核tag，编译manifest记录组→成员→最终节点路径。校验空组、引用缺失、递归引用、重复tag、失效前置/落地代理。空组默认阻止应用，不自动替换DIRECT。

支持手动/自动策略组引用可用的节点或已支持组图；高级嵌套先校验无环。没有内核真实支持的策略类型不增加伪按钮。删除被规则或运行图引用的组前展示引用清单并要求处理。

## 10. 连接详情、日志与诊断

### 10.1 连接列表

明确命名“连接列表”，从首页状态区、节点更多和日志页进入。显示目标域名/IP、网络、上传下载、开始时间、匹配规则表达式、代理链。支持搜索、筛选直连/代理/拒绝（仅实际采集到的状态）、查看单条详情和关闭连接。

取不到应用归属时不显示推测应用名称；取不到目标域名时显示IP，空字段显示“未提供”，不将字符串`undefined`拼到界面。

### 10.2 “为什么走这条线路”

优先提供真实连接证据：目标→内核报告的规则→策略组链→最终节点，并标注运行revision和采集时间。当前内核`rule`可提供规则表达式，`rulePayload`为空，不能伪造完整结构化payload。

只有与编译manifest唯一对应时才链接本地规则名称；存在歧义时展示内核原文，不错误定位编辑器。若后续需要唯一规则ID，作为K3可选内核元数据扩展实施并单独验证。

### 10.3 输入域名的规则解释工具

提供“已有连接中查找”作为第一入口；没有真实连接时提供“配置分析”。配置分析要求显式输入必要的目标、端口和协议，可选DNS解析；无法判定嗅探、源IP、应用归属、动态规则集条件时显示未知条件，不能宣称模拟结果就是实际选路。

如用户选择实际连通测试，则说明会对该目标发起网络请求，只访问用户输入的目标，不后台探测整个网站清单。结果标记是否真实请求、所用revision与时间。

### 10.4 日志清除与流量重置

- “清空当前日志视图”记录清除时文件偏移和文件身份，下次tail从该位置继续；新日志仍可见，旧日志不重现。文件轮转/截断后按新文件身份处理。
- 导出默认当前过滤范围，可选择本次会话全部；导出前默认脱敏URL凭据、订阅token、密码和密钥，允许用户预览。
- “重置显示累计流量”使用扩展会话的基准偏移，包含epoch；UI与通知从同一基准计算，轮询不再写回旧显示值。
- 节点历史流量、会话流量和显示累计值分别命名；重置某一项不清除另一项，除非用户选择明确范围。
- 日志等级成为结构化事件字段；历史纯文本保留兼容，不再仅靠整行包含ERROR识别所有应用错误。

### 10.5 诊断包

包含版本、实际内核能力、系统API级别、运行/保存revision、错误类别、脱敏日志、检测参数及结果摘要；不默认包含完整节点密钥或私人订阅URL。生成后用户选择保存或分享，不自动上传。

## 11. 订阅、缓存与用户覆盖

### 11.1 列表与详情

订阅卡显示名称、节点数、最后成功更新时间、最近尝试结果。服务端提供时显示已用/总流量、到期日期；未提供显示“未提供”，不能用0GB/1970日期替代未知。

服务端流量和本机统计明确分开，服务端统计不是实时计费保证。到期时间按用户系统时区显示，解析与存储使用标准时间值。

常用按钮为更新、详情；分享、导出、清空节点、删除进入更多，危险操作不与更新挤在一行红色小字中。更新全部显示逐订阅结果，一个失败不覆盖其他结果。

### 11.2 添加与导入

“添加订阅”使用名称＋URL，扫码/剪贴板/文件并列为导入方式。识别URI节点与订阅URL时给出实际识别结果；未知格式显示原因。解析后展示将导入的节点/组数量、跳过数量与类型；无有效节点不提交为空订阅覆盖旧数据。

导入成功后提供“查看节点”“检测可用性”；不强制立即连接，不未经确认替换正在使用的配置。

### 11.3 更新事务

流程为获取→解析→规范化→身份匹配→构建候选图→合并覆盖→校验→差异预览/按既有设置提交→写入新快照。任何一步失败都保留旧快照及有效缓存。

304表示内容未变，只推进成功检查时间，不清节点，不改用户覆盖。错误响应、200空正文、未知格式、仅不支持节点等分别记录，不全归为网络超时。

更新与检测、编辑、删除通过同一仓库串行提交；网络下载和解析在写锁外，提交前比较基线revision并重算合并，避免长时间锁住UI。

### 11.4 原始内容与用户覆盖

新增三层数据：订阅源快照`SubscriptionSourceSnapshot`、用户覆盖`UserOverride`、最终有效视图`EffectiveProfile`。

覆盖包括别名、收藏/置顶、排序、展示分组、用户选择的策略成员及显式允许的传输字段覆盖。基础UI对传输修改提供“跟随订阅／保留我的修改”，高级覆盖展示字段级差异。原始订阅内容不被编辑器直接覆盖。

节点身份优先使用来源提供的稳定标识；没有时用订阅ID＋规范化传输特征作为匹配依据，显示名称不作为唯一身份。重复且无法唯一对应时产生冲突项，不把一个覆盖随机套给另一个节点。用户别名和订阅名称分别保留。

远端改名但身份相同：保留覆盖；远端参数变更：更新原始层并标注覆盖冲突；远端删除：默认从有效订阅移除，保留一段可恢复的覆盖记录，并可显式“转为手动节点”。不能将已删除服务器悄悄保留成仍属订阅的可用项。

### 11.5 当前使用节点被删除

运行会话保留原编译快照；新保存配置显示待应用及“当前节点已从订阅移除”。有有效替代选择后才应用；重启后无法使用已删除节点时给出选择入口，不能默认任意代理或DIRECT。

自动更新遵守用户原设置，保留关闭状态和间隔；不会因新UI启用后台频繁更新。传输期长时任务仍只用于真实下载，不扩展为VPN会话保活。

## 12. 设置与配置应用

### 12.1 设置分类

| 类别 | 示例 | 保存/生效方式 |
|---|---|---|
| 即时外观与浏览 | 深浅色、字体跟随系统、地址显示、列表密度 | 校验后即时保存与刷新，不重启VPN |
| 下次操作参数 | 检测URL/并发、订阅更新偏好 | 保存后用于下一次任务；不更改正在运行任务快照 |
| 运行配置参数 | DNS、IPv6、嗅探、规则、模式、应用名单、入站、策略图 | 存草稿→验证→应用；需重连时统一一次执行 |

设置页面提供搜索，基础显示常用项，高级项分区折叠且显示已有非默认值摘要。选择器显示本地化纯文本，避免Resource对象转字符串。

### 12.2 全局待应用条

运行配置被修改后，节点、分流、设置页统一显示“有3项修改待应用”，点击查看变更列表和影响：需要重连／可热切换／仅下次任务。提供应用、稍后、放弃草稿。退出页面保留草稿，不能把保存当作运行中生效。

模式切换属于高频运行配置操作：点击立即给出反馈并提交一次应用事务；离线只保存下次连接模式。连续切换合并到最终目标，不排队重连三次。

### 12.3 应用事务状态机

草稿→校验中→已保存待应用→应用中→运行确认／应用失败。保存revision、请求revision、运行revision分别存储。

1. 捕获基础revision、候选配置、资源manifest和依赖图。
2. 静态校验应用范围、节点/组/规则引用、参数、缓存可用性。
3. K1内核校验通过后生成候选快照；校验能力不足时标为未验证，不能将成功启动验证用文字替代。
4. 提交保存快照；连接中由单一生命周期协调器重连，离线记录下次连接配置。
5. 扩展加载精确revision和hash，确认内核启动及平台名单；回报应用结果。
6. 仅匹配operationId/sessionId/revision的确认可结束当前事务；迟到事件忽略并记录。
7. 失败有可用旧快照时尝试一次恢复；恢复也可能失败，失败后显示真实断开/未知状态，不无限重试。
8. UI被杀不取消一个已进入扩展的有效应用事务；重开后查询状态，避免重发同一次操作。

重连并非真正无中断的原子交换。新连接失败后旧连接可能已经断开，界面必须诚实说明。恢复默认、恢复备份、订阅更新引起的网络变化也走同一事务。

### 12.4 设置的真实性

每个开关必须列出消费方。触感反馈接真实平台API并处理用户系统设置；液态玻璃若作为设置保留，必须确实影响约定组件且不破坏既有半透明速率条。不可用的TUN栈或未获权限能力不提供可选但无效的值。

“恢复本分区默认”展示将改的字段并可撤销草稿；“恢复出厂”在工具深层页面，说明将断开VPN并删除哪些本地数据，执行前可导出备份。

## 13. 视觉、布局与无障碍

### 13.1 视觉规格

- 使用现有UiSpec和资源颜色作为统一入口，新增语义token，避免每页独立硬编码。
- 规划基础间距4/8/12/16/24vp；手机侧边距16—24vp按断点选取，最终以真机阅读与触达为准。
- 标题、正文、辅助文字建立三级层次；常用正文约14—16fp，辅助信息约12—13fp，支持系统放大，不以固定高度截断内容。
- 点击热区目标至少44×44vp；小图标可小，但热区不能同样缩小。高频文本按钮不得密集挤在行尾。
- 延迟和速率使用等宽数字；单位和小数位一致，避免列表抖动。
- 保留当前用户确认的底栏半透明底色和`.backdropBlur(20)`方向；不换成会填实背景的组件材质。浅/深色资源均独立验收。
- 状态采用文字＋图形＋颜色；150/400ms延迟分档继续保留，但TCP成功不能仅凭绿色冒充HTTP可用。
- 动效以状态转换和轻量反馈为主；尊重系统减少动态效果设置。滚动列表不叠加持续昂贵光效。

### 13.2 响应式布局

| 宽度 | 布局 |
|---|---|
| <600vp | 单列，详情进入二级页，抽屉保留 |
| 600—839vp | 视可用宽度使用双栏或紧凑导航；不强行挤两份完整表单 |
| ≥840vp | 列表＋详情双栏，主从选择稳定，空详情有说明 |

断点沿用现有600/840基础值，旋转与分屏实时适配。双栏切回单栏时保留所选详情和返回关系，不能丢编辑草稿。连接卡、节点列表和详情有各自滚动边界，避免嵌套滚动抢手势。

### 13.3 无障碍与输入

所有图标提供可访问名称、状态及禁用原因；选择、正在使用、检测进度可被读出。焦点顺序随布局合理变化；键盘和屏幕阅读器可完成排序、选择、取消与应用。

测试系统字体100%/130%/最大档、长中文、长英文、长节点名、IPv6地址、横屏、分屏、浅深色。输入过程不得因key变化重建组件丢焦点。粘贴敏感URL不自动显示完整token，分享前提供脱敏预览。

## 14. 数据模型、迁移与兼容

### 14.1 现状与问题

当前节点、组、设置、订阅、规则分别存Preferences；部分写入经过`mutateProfiles`，部分仍全量`saveProfiles`。UI与VPN扩展有独立缓存。只给UI改名不能解决读写竞争、多个集合提交到一半、保存/运行状态不一致等问题。

因此引入一个配置仓库作为唯一业务写入口，逐步把直接Preferences调用收口。保持现有模型外观适配层，避免一次把所有页面和存储同时推翻。

### 14.2 建议的实体与字段

| 实体 | 新增/明确字段 | 权威关系 |
|---|---|---|
| ConfigSnapshot | schemaVersion、revision、parentRevision、createdAt、checksum、resourceManifestId | 一份可复现的保存配置 |
| Profile | 稳定ID、sourceSubscriptionId、sourceIdentity、配置hash | 节点身份与传输内容分开 |
| SubscriptionSourceSnapshot | subscriptionId、fetchRevision、原始规范化节点/组、响应校验器 | 订阅来源事实 |
| UserOverride | sourceIdentity、字段patch、别名/收藏/排序、冲突状态 | 用户意图，不被源更新覆盖 |
| StrategyGroup | 稳定ID、type、成员引用、默认成员、检测参数、来源 | 展示分组以外的实际策略 |
| RouteRule | 稳定ID、priority、source、typed conditions、targetRef、平台状态 | 编译与编辑有同一身份 |
| RuleSetResource | id、sourceURL、format、当前验证hash、版本、下载/验证时间、错误、失败策略 | 缓存验证事实 |
| ProbeResult / ProbeRun | §6字段、完成与保存数量、目标快照 | 检测事实，不写回原始订阅内容 |
| RuntimeSnapshot | sessionId、generation、operationId、appliedRevision、根出站、实际成员、状态、heartbeat | 扩展/内核确认的运行事实 |
| ApplyDraft | baseRevision、changes、validationErrors、impact、savedAt | 保存的修改意图 |
| CompiledManifest | configHash、规则顺序、tag映射、资源hash、能力需求 | 界面与内核配置之间的映射 |

所有跨实体引用使用稳定ID。显示名、URL、数组位置和瞬时tag均不作为持久化主键。旧`subUrl`作为兼容字段保留，迁移出稳定subscriptionId后URL变化不再造成整个来源身份丢失。

### 14.3 配置提交的存储策略

目标实现为版本化不可变配置快照＋活动manifest指针；Preferences只保留小型兼容键和界面偏好，不再把多个独立`put/flush`当成跨集合事务。

网络/规则字段以快照为权威，外观/浏览偏好以偏好仓库为权威，同一字段不在两边双写。旧AppSettings调用通过适配层组合读取，不能形成两份都可修改的“全局设置对象”。

1. 候选快照写入应用私有目录临时文件，完整序列化后校验checksum并刷盘。
2. 在同一文件系统将候选文件完成重命名；发布活动manifest指针使用SDK实际支持的替换方式。
3. 启动时验证manifest和快照完整性；中断留下的临时文件不作为活动配置。
4. P0验证SDK文件替换/刷盘语义；若平台不能保证原子替换，采用双槽manifest＋单调revision＋校验恢复机制，不能用普通覆盖写冒充原子性。
5. 配置仓库单写者负责提交；扩展只读取指定revision，运行遥测写入单独会话日志，不再在扩展中改整个配置节点数组。
6. 读取者在拿到一份有效快照后不混读另一修订的规则/节点；资源manifest与快照共同引用。
7. 检测结果、流量与日志采用独立记录，避免每秒重写完整配置快照；投影回旧模型时通过仓库控制。
8. 垃圾回收不得删除活动、运行中、回滚点和未完成迁移引用的资源。

这是一项明确的工程工作，不能仅把现有save函数重命名成Repository就宣称事务完成。记录失败位置，并通过中断注入检验恢复。

指针命名必须区分`draftManifest`、`savedManifest`和扩展持有的`appliedRevision`。保存成功可以推进saved指针，但不能因此推进applied。应用失败且运行恢复旧快照后，用户的新保存内容仍为待应用；只有明确放弃草稿/恢复配置才回退用户意图。

### 14.4 Schema v4→v5迁移

当前备份schema=4，导入器接受1—4。新方案使用schema=5，继续读取1—4，并拒绝未来未知schema，给明确版本提示。

迁移步骤：

1. 采集旧配置源快照和hash；创建应用内升级恢复点。排除签名材料、构建凭据，不把它们打进业务备份。
2. 解析和逐实体校验，任何整体格式错误都不覆盖旧数据；可隔离的坏记录列出恢复报告。
3. 为旧订阅、规则、策略实体分配稳定ID，并写出映射表；节点既有ID保留。
4. 将`isSelector/autoSelect`迁成策略组类型；若同时为true，按当前autoSelect优先的有效行为迁移，并记录原字段。
5. 展示分组、折叠状态、当前订阅视图、收藏和排序迁移；旧首页空groupId的合法含义保留。
6. 旧节点检测结果迁成来源未知的历史结果，不写虚假的方法与状态码。
7. 分应用保留条目/名称/勾选；识别include空名单、超上限和非法包名，标为待处理。
8. 历史包名规则按§8.5保留原文并标记；不删除条件、不扩大规则。
9. 订阅已有用户修改缺少原始源可对比时，先以现有有效值作为兼容覆盖基线，首次成功拉取后做差异确认；不能猜测哪些字段来自用户。
10. 写入候选v5快照，重新读取并校验全部引用；成功后才切活动指针。
11. 记录迁移版本与结果；重复启动幂等，不重复生成ID或预置项。
12. 升级时已有VPN会话继续使用旧运行快照；迁移完成不自动执行可能改变策略的重连。

### 14.5 回滚与备份

- 回滚优先指应用内回到上一份已验证配置，不依赖降级安装同versionCode的软件包。
- 保留迁移前v4业务备份；v5可导出兼容v4副本，但必须列出旧格式无法表达的覆盖、检测历史和策略参数，用户选择后生成，不能宣称无损。
- v5导出覆盖、组选择及规则集元数据；默认不嵌入无限缓存、日志和运行锁。可用缓存资源可作为可选附件，不把它当订阅可达性保证。
- 恢复先校验→预览→生成候选快照→应用；失败保留原配置。涉及断开与重连的行为必须明确显示。
- 检测、订阅更新、恢复出厂、备份恢复之间有明确的互斥与取消规则；不得一边恢复一边写回旧任务结果。

## 16. 运行协议与内核能力

### 16.1 版本化IPC

新增事件信封至少包含`protocolVersion / sessionId / generation / sequence / operationId / appliedRevision / configHash / emittedAt`。状态、流量、实际组成员和应用确认均可关联同一会话。

UI按session与sequence过滤倒序、重复和迟到事件；收到序列断层可请求完整快照。时间戳仅用于展示与诊断，不替代sequence排序。UI重建后先查询全量运行快照，再订阅增量，处理两者交叠的事件去重。

命令包括连接指定revision、停止指定会话、应用revision、查询状态；对于同operationId重试返回已有结果，不重复启动。关键指令限制在本应用现有通信边界内，核对发布者/订阅权限，不增加可被其他应用随意调用的公共控制入口。

### 16.2 Clash API约定

继续监听现有127.0.0.1＋随机secret，统一鉴权和错误处理。读取`/proxies`的now/all/history建立实际成员视图；PUT后GET确认。刷新请求不重叠，页面退后台降低/暂停UI轮询，扩展必要运行监测独立进行。

错误分401/403鉴权、连接拒绝/API关闭、超时、响应格式无效、目标不在运行图。API缺失时显示能力受限，并提供明确的重连路径，不伪造组状态或连接明细。

### 16.3 K1：配置与SRS验证能力

现有API没有完整独立check入口。先做实现验证，再接产品“已验证”状态：

- 新增版本化能力查询，报告实际库支持的验证、检测判据、会话取消和传输能力。
- 配置校验：解析真实内核schema、验证注册类型与引用；不得调用会抢占TUN/监听端口/启动任务的正式Start。box.New是否有文件或其他副作用需在P0核对并隔离临时输出；无法安全执行的检查拆为结构校验和运行验证两层。
- SRS校验：完整解析内容、版本与规则，错误带位置；不能只识别文件头。
- 校验结果注明范围，例如“schema和引用通过”不等于系统权限、远端认证和所有网络通路已经验证。
- 新导出使用新名称/版本后缀，NAPI按能力选择；保留CGoStart/Stop/SetTunFd以及legacy/V2检测导出原签名。
- 旧库缺能力时不能启用依赖该能力的“已验证资源”流程；构建发布必须带正确新库，不能把兼容回退当最终交付。

### 16.4 K2：检测会话取消与迟到回调

如§6.5实测现有锁与导出不能保证session边界，新增sessionId版本的start/probe/stop/cancel协议。取消context与迟到start销毁在Go层落实，NAPI回调带会话ID；桥接超时不会释放一个实际上仍在运行的原生任务槽。

K2的目标是保证“旧任务不会停止或污染新任务”，不承诺Go或系统永久阻塞时一定能安全强制回收。不可恢复时明确报告检测不可用，VPN主会话继续独立运行；不通过dlclose活跃Go运行时强行恢复。

### 16.5 K3：可选结构化规则标识

基础诊断已可使用内核rule表达式与chains满足REQ-12。只有当实现精确跳转编辑需要而现有manifest无法唯一对应时，增加可选规则ID/索引元数据，必须与运行configRevision绑定；旧API仍返回兼容字段。不得为了好看的规则名称把推断结果当成真实内核报告。

## 17. 平台、权限与既有约束

1. `module.json5` 的 VPN extension type保持`vpn`。不借UI重构更改系统能力类型。
2. 不新增未获ACL的`KEEP_BACKGROUND_RUNNING_SYSTEM`、`USE_FRAUD_APP_PICKER`等权限。
3. 当前`dataTransfer`声明保留；长时任务只用于真实传输期，不把它恢复为整段VPN会话保活。
4. 当前READ_PASTEBOARD与隐私政策/发布profile口径保持一致；变更任何权限需复核SDK定义并运行permission-policy测试，不能照抄旧文档中已经被纠正的删除建议。
5. 出站保护、物理接口绑定、IPv6和TUN fd注入保持独立回归；UI改造不意味着这些底层风险自动消失。

7. 内核版本与应用版本分别读取/展示；关于页实际查询能力或版本，不再仅靠硬编码说明。
8. 修改内核包装/补丁后必须重编.so＋重新打包HAP，并验证导出与包内hash；只改Go源码而不更新冻结成品不算完成。

## 18. 故障处理与恢复策略

| 故障 | 必须行为 | 不允许行为 |
|---|---|---|
| 保存磁盘满/权限失败 | 保留草稿、显示未保存；不重启VPN | 提示成功、丢草稿、用旧名单重连 |
| include名单空/超限 | 阻止连接/应用，定位修复 | 省略名单变全应用、静默截断 |
| 规则集首次失败 | 保留旧运行快照，新配置待修复 | 自动删除规则集后继续连接 |
| 规则集缓存损坏 | 回退另一份已验证版本或阻止应用 | 只凭文件存在继续使用 |
| 单节点schema错误 | 分批隔离，其他节点做原方法检测 | 整批假绿、把QUIC跳过当成功 |
| native迟到/未停止 | 任务generation隔离、等待确认或报告不可用 | 立即创建冲突新实例 |
| 订阅200空内容/解析失败 | 旧数据保持，给出失败原因 | 清空旧节点当更新成功 |
| 更新删除运行节点 | 保持会话快照、要求选择替代目标 | 重开后随机选节点或DIRECT |
| 热切换失败 | 读回实际状态、显示失败 | 先更新勾选和正在使用再忽略错误 |
| UI被回收 | 重建后查询实际会话与操作结果 | 重复connect造成隧道互拆 |
| 扩展/内核崩溃 | 记录会话错误，按用户恢复设置处理 | 无界自动重启、静默长期显示已连接 |
| 控制API关闭/端口冲突 | 功能降级说明，基础VPN状态仍来自扩展 | 列表空白伪装没有连接 |
| 配置应用失败 | 一次有界旧快照恢复，显示真实结果 | 声称必定无中断、无限重试 |
| 迁移中断 | 回到完整旧快照或恢复候选 | 混用一半v4、一半v5 |
| 恢复备份时仍有旧任务 | 取消或等待并隔离旧generation | 恢复后被旧检测/订阅任务写回 |

恢复操作都写入结构化审计事件，包含revision、会话和简短错误；不记录明文节点密码。

### 20.2 实施中的评审点

- P0结束：冻结字段契约与状态语义，核实存储/桥接可行性；若技术验证推翻设计，先修订方案再接UI。

## 23. 性能与资源预算

以下是拟定验收目标，不是现有测量结果。P0记录基线，P6用同设备同数据比较；遇到目标不合理先给实测依据修订，而非无声跳过。

| 项目 | 初始目标 | 测量方式 |
|---|---|---|
| 点击反馈 | 常用按钮100ms内出现视觉/文字反馈 | 设备操作时间戳＋界面帧 |
| 搜索 | 1000节点停止输入后300ms内更新可见结果；5000节点≤700ms | 固定查询集，至少20次取P95 |
| 切换一级页 | 暖态首个可交互内容≤300ms，磁盘慢时先显示明确加载 | 同设备多次记录，报告P50/P95 |
| 检测UI合并 | 最多每300ms集中刷新一次大列表，取消反馈≤100ms | 5000节点模拟回调与真机操作 |
| 检测取消收尾 | UI立即进入取消中；单个有界任务在其超时预算内收尾 | 记录请求/最后结果/native stop确认 |
| 热切换 | 立即反馈，局域回环控制往返目标≤1s，不保证远端新连接立刻可用 | PUT/GET时间戳、TUN session保持 |
| UI轮询 | 同一端点不重叠，后台不持续刷新不可见列表 | 请求计数与生命周期日志 |
| 流量显示 | 以实际采样间隔算速率，允许轮询抖动，不能默认每次恰好1s | 注入0.5/1/2s采样间隔 |
| 配置写入 | 无每秒全量配置快照写；网络下载与UI解析不持有写锁 | 存储操作计数与时序 |
| 资源释放 | 连续20轮检测、20次连接/切换后无持续增长的socket/任务/句柄 | 主机计数＋设备资源趋势 |
| 内存 | 固定数据集重复操作后内存趋稳，不给尚未实测的绝对MB承诺 | 空闲/峰值/恢复后的曲线 |
| 电量/后台 | 不增加无关永久轮询或后台常驻检测；记录30分钟对照 | 相同网络和设备对照观察 |

长任务必须可见、可取消、有超时。网络条件不稳定时报告真实耗时与原因，不能拿网络等待当UI卡顿，也不能把UI卡死全部归因于网络。

## 24. 风险登记与发布门槛

### 24.1 主要风险及应对

| 风险 | 影响 | 应对与验收 |
|---|---|---|
| 大规模UI重构同时改数据 | 回归难定位、数据丢失 | 先仓库与协议、再页面；逐工作包回归 |
| 新旧模型双写 | 来源分裂、覆盖丢失 | 明确唯一权威；兼容字段只投影；列清删除双写时点 |
| 固定库与新NAPI不一致 | 崩溃/能力静默缺失 | 版本化导出、能力检查、包内hash验证 |
| 状态异步与旧事件 | 假连接、错误正在使用节点 | session/generation/sequence＋读回确认 |
| 设置保存与应用混淆 | 用户以为分流已生效 | 独立saved/applied revision与全局待应用条 |
| 自动恢复扩大策略 | 应用被意外代理/直连 | 明确失败策略；空组空名单阻止；不静默改目标 |

| 文件替换不原子 | 半份配置 | P0验证；双槽manifest及校验恢复 |
| 系统没有某权限 | 假功能入口/上架受阻 | 实际SDK与profile核对；不加受限权限 |
| 只靠主机测试 | 真机TUN/接口问题漏检 | P6设备验收硬门槛 |
| 既有测试描述已过时 | 测试绿但功能错 | 验证行为与证据，更新故障断言含义 |

## 25. 完成口径与施工前检查

### 25.1 每条建议的完成定义

完成必须同时满足：**用户找得到入口→操作能执行→结果来自真实业务/内核→能正确保存和恢复→失败有明确处理→通过对应平台验收**。

例如：

- “策略组完成”不是只有`autoSelect`字段，而是有编辑入口、实际生成配置、运行成员读回、切换与故障证据。
- “分应用完成”不是日志打印了包名，而是两款实际测试应用的出口符合名单，空名单也不扩大范围。
- “测速完成”不是有一个绿色数字，而是方式/目标/判据/时间/路径可解释，坏节点不污染其他结论。
- “规则诊断完成”不是前端猜出一个规则名，而是展示实际运行revision对应的内核证据，无法得知的部分标未知。
- “UI完成”不是单张空态截图，而是关键状态、长列表、最大字体、手机平板都可操作。
- “全面改造完成”不是完成P3首页后停止，而是所有工作包及发布门槛达标。
